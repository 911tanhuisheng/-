# 毕业设计论文与答辩准备指南

## 建议题目

《融合图像识别的智能化在线编程判题系统设计与实现》

## 研究目标

针对传统 OJ 只能处理文本标准输入输出的问题，设计一种将图像作为测试输入的在线编程评测方法。系统完成题图采集、智能标注、结构化出题、隔离执行、多策略判题和结果反馈，并以通用目标检测、安全帽场景检测、OCR 和图像属性分析验证方案可行性。

## 可写成创新点的内容

1. 将图像文件安全注入无网络 Docker 沙箱，学生程序通过标准输入读取容器内只读路径。
2. 面向不同视觉任务设计模型路由：YOLO 通用检测、自训练安全帽检测、EasyOCR、OpenCV。
3. 将传统精确匹配扩展为数量容差、类别标签、检测框 IoU、OCR 编辑距离和数值容差判题。
4. 采用公开样例与隐藏图像测试集分离，解决单图题直接硬编码答案的问题。
5. 管理端实现“图片采集—AI 标注—题面生成—教师复核—发布”的半自动命题流程。

## 必做实验

| 实验 | 自变量 | 指标 |
|---|---|---|
| 置信度实验 | 0.15 / 0.25 / 0.35 / 0.50 | Precision、Recall、mAP |
| 模型对比 | YOLOv8n / 自训练安全帽模型 | 各类别 mAP、推理时间 |
| 容差判题 | 数量误差、OCR 距离、IoU 阈值 | 正确接受率、错误接受率 |
| 沙箱开销 | 普通 Python / YOLO / OCR | 启动、推理、总判题时间、内存 |
| 安全实验 | 网络访问、越权路径、超时、超内存 | 是否被阻止、错误类型 |
| 防硬编码实验 | 仅公开图 / 加入隐藏图 | 硬编码程序是否通过 |

## 当前可直接写入论文的模型结果

独立测试集 Precision 为 0.649、Recall 为 0.704、mAP50 为 0.676、mAP50-95 为 0.462。`head` 与 `helmet` 的 mAP50-95 分别约为 0.672 和 0.681，`person` 约为 0.033。论文必须如实分析类别不均衡，不能只报告总体指标。

## 答辩演示顺序

1. 创建普通文本题，展示传统 OJ 判题。
2. 创建安全帽目标计数题，上传 1 张公开图和多张隐藏图。
3. 展示 YOLO 检测框、自动题面、模型选择和标准答案。
4. 学生运行公开样例并提交正确程序。
5. 提交硬编码公开答案，展示其被隐藏图片判错。
6. 提交语法错误、超时程序，展示结构化错误反馈。
7. 展示 Docker `network=none`、MinIO 可信图片读取和提交结果自动刷新。

## 验收标准

- 正确代码通过公开与隐藏用例。
- 硬编码公开答案无法通过隐藏用例。
- 非 MinIO 图片不能进入正式题库。
- 图像题只能提交 Python，普通题支持原有语言。
- 编译错误、运行错误、超时和系统错误均能区分。
- Sandbox 不允许联网，容器退出后自动清理。
- 判题服务异常时提交最终进入失败状态，不永久等待。
